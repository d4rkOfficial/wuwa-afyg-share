# 椰果工坊 · 前端 UI/UX 优化方案

> 本文是对现有界面的**定量诊断 + 分层重构方案**，用于取代 `docs/ui-layout-spec.md`（v1）中的 R1。
> 全部结论可在仓库里复核：数字来自对 `globals.css` / `ui.css` / `src/**` 的实测（对比度按 sRGB 相对亮度计算），
> 问题都带 `文件:行号`。

---

## 一、先给结论

**"设计很差"不是审美问题，是三个可量化的结构性缺陷叠加：**

| # | 根因 | 一句话 | 关键证据 |
|---|------|--------|----------|
| **R1** | **唯一的层次手段是 1px 边框，而边框对比度只有 1.3:1** | 全站取消阴影后，`border` 成了唯一的分区信号；但它低于 WCAG 3:1 下限一倍多，于是"处处是框、处处不分组"，视觉上就是一团灰色细线 | `--card-border` 对 bg 1.38:1 / 对 card 1.30:1（规范要求 3:1）；`border-(--card-border)` 在源码出现 **204 次**；`box-shadow: none !important` 全局置零（`globals.css:114-118`） |
| **R2** | **同时存在 4 套在用的视觉语言 + 2 套意外的** | 同一产品里 `mg-*`（杂志）、`ui-*`（v2）、`agent-*`（DSH 控制台）、`edit/ws`（VSCode 外壳）各管一块；v2 建好了却只覆盖 Buff 编辑台 | `.mg-*` 211 处引用；`.ui-*` 44 个类只有 7 个文件用；`.agent-*` 208 处引用且自带调色板+字族 |
| **R3** | **尺度完全失控** | 声明 5 档字号 / 1 档圆角 / 6 档间距，实际渲染 14 档字号 / 10 档圆角 / 395 处半格间距 | 手写 `text-[10px]`×**60**、`text-[11px]`×**95**；圆角实际出现 0/2/3/5/6/8/10/12/999；`rounded-sm`×**285** |

**外加三个高感知缺陷：**

- **R4｜强调色既是"选中态"又是装饰**，而它作为填充色时前景对比度只有 **3.41:1**（深色默认主题，AA 需 4.5）——主按钮、选中行、`::selection`、下拉选中项全中招。
- **R5｜首屏不稳定**：首页 SSR 串行 6 次往返（其中 2 次是 `no-store` 的第三方 CDN），加载态是整页转圈；卡片里的角色色块在 hydration 后才上色，**每 12 张卡片会闪一次**。
- **R6｜交互反馈缺失**：焦点环只有一条 `:focus-visible{border-color}`，凡是"没有边框的可点元素"（侧栏行、主题按钮、菜单项、分段按钮）**键盘焦点完全不可见**；两个主按钮反而因 `border-color: transparent` 自描同色边。

**处方（4 层，4 批 PR）：**

```
P0 地基      统一 token / 修对比度 / 修焦点 / 改分区规则 / 删死代码        0.5–1 天
P1 组件层    只保留一套 primitive，业务页不再手写长 class 串             2–3 天
P2 页面层    首页 / 详情 / 上传 / 我的 / 数据浏览 / 编辑台 逐个重排      3–5 天
P3 品牌层    属性色与角色头像收敛为"一处高光"，字体策略定调              1 天
```

**做完 P0 就能看到最大的一档观感提升**（页面会立刻"安静"下来且结构清晰），P0 不改任何业务逻辑、只改 CSS 与删代码，回滚成本接近零。

## 二、诊断证据

### 2.1 层次失效：边框与表面对比度实测

| 配对 | 深色 | 浅色 | 用途 | 判定 |
|---|---|---|---|---|
| `fg` / `card` | 14.10 | 15.66 | 正文 | 达标 |
| `muted` / `card` | 6.06 | 5.45 | 次要文字 | 达标 |
| **`accent` + `accent-fg`（填充按钮）** | **3.41** | 4.72 | 主按钮/选中行 | 不达标 **深色不达 AA** |
| `accent` 作文字色 / bg | 5.47 | **4.44** | 强调链接 | 注意 浅色不达 AA |
| **`card-border` / bg** | **1.38** | **1.31** | 卡片轮廓 | 不达标 3:1 不达 |
| **`card-border` / card** | **1.30** | **1.40** | 卡片轮廓 | 不达标 3:1 不达 |
| `card` / bg（表面差） | 1.06 | 1.06 | 卡片"浮起" | 不达标 几乎为零 |
| `input-bg` / bg | 1.03 | 1.02 | 输入框可辨 | 不达标 几乎为零 |
| `.agent` `fg-3` / `panel`（浅色） | 6.58 | **3.63** | AI 控制台次要文字 | 不达标 浅色不达 AA |
| `--overlay` 遮罩后 dialog / 遮罩 | **1.10** | — | 弹窗浮起 | 不达标 与发丝线同强 |

**结论**：文字对比度基本没问题（`muted` 6:1 是合理的克制值），**坏的是"结构"这一层** —— 在一个禁用阴影的系统里，唯一的层次手段低于可感知阈值，于是：

1. 卡片读不出卡片 → 用户不知道哪里是一个整体；
2. 为了弥补，代码里不断加边框、加分割线（204 处）、卡片套卡片（`mg-card` → 分区边框 → `.slot-card` 三层嵌套）；
3. 结果"框比内容还多"，视线无处安放 —— 这正是"看起来很差"的直接来源。

### 2.3 尺度失控

| 维度 | 规范声明 | 实际渲染 | 违规证据 |
|---|---|---|---|
| 字号 | 5 档（12/13/15/20/26） | **14 档**（9/10/11/11.5/12/13/13.5/15/16/17/20/24/30/36） | `text-[10px]`×60、`text-[11px]`×95、`text-[9px]`×1；`--text-title` 与 `--text-lg` 在 CSS 中 **0 使用** |
| 圆角 | 1 档（6px） | **10 档** | `@theme` 里 `--radius-xs…3xl` 8 个 + `--r-sm/md/lg` 3 个；`.ui-btn` 8px 而它自己的 `--sm` 6px；`.agent-user`/`.agent-modal` 12px；4 个 radius token **零引用** |
| 间距 | 6 档 8px 网格 | CSS 里 49 处守规，TSX 里 **395 处**半格 | `gap-1.5`×86、`py-1.5`×74、`py-0.5`×59、`px-1.5`×51 |
| 按钮 | 2 档高度 | 至少 6 种手写 | `px-2 py-1 text-xs` / `px-3 py-1.5 text-sm` / `px-4 py-2 text-sm` / `h-8` / `size-9` / `size-10` 混用（顶栏同一行里 `h-8` 与 `size-9` 并存：`header.tsx:12` vs `:138`） |

**并且类型 token 被劫持了**：`ui.css:8-22` 在**无 `@layer` 的 `:root`** 上重新声明了 `--text-xs / --text-sm / --text-lg / --text-xl`，优先级高于 Tailwind 的 `@layer theme`。编译产物里 `.text-sm{font-size:var(--text-sm)}` 因此变成 **13px**、`.text-lg` 变成 **15px**。作者写 `text-sm` 期望 14px 却得到 13px，于是大量地方改成手写 `text-[11px]` 去"找感觉"——**R3 的一半是被这条规则逼出来的**。

### 2.4 字体

- `public/fonts/fang-xin-shu.ttf` = **5.43 MiB**，`format('truetype')`，无 woff2、无子集、无 `local()`，`font-display: swap`（`globals.css:4-8`）。
- 它同时是 `--font-sans`、`--font-serif`、`--font-mono` ——**全站唯一的字**，包括数字、分享码、JSON、SQL。
- **正确的 woff2 其实已经在仓库里但从未被引用**：`public/fonts/jetbrains-mono.woff2`（30.7 KB，`grep jetbrains src/` = 0）。
- `--font-mono: 'FangXinShu', var(--font-mono, ui-monospace, monospace)`（`globals.css:31`）是**自引用循环**，按 CSS 规范取 guaranteed-invalid 值，于是 `var(--font-mono, …)` 的调用点回落到 `ui-monospace`，而 `font-mono` 工具类的调用点回落到…继承手写体。**同一份"等宽"文本在不同文件里长得不一样。**
- `.agent-surface` 的 `font-family: var(--font-geist-sans)`（`globals.css:731`）——**`--font-geist-sans` 全仓库未定义**（没有 `next/font`），所以 AI 控制台静默落到系统无衬线字体。第三套字族则是 `.buff-admin-shell` 强制的 PingFang/雅黑（`globals.css:174-191`），于是 `/admin/projects`（黑体 600）和 `/edit/substat-sets`（手写体 400）像两个产品。

**为什么这一条最伤观感**：仿心书是手写/毛笔感的 CJK 字体，拉丁数字是比例宽度、大概率没有 `tnum` 特性。而这个站是**拉表排轴的数值工具**——在 11px 的手写体里读 `1.234 / 12.5% / ×2.4`，是所有问题里最直接的一刀。

### 2.5 交互状态与键盘可达性

- 全站只有**一条** focus 规则：`:focus-visible{outline:none; border-color:var(--accent) !important}`（`globals.css:121-124`）。
- `border-color` 需要有边框才可见。以下元素**自身没有边框**，焦点因此 100% 不可见：`.workbench-item`（`globals.css:536`）、`.agent-rail-item`、`.ui-menu-item`、`.ui-seg-item`、`.theme-toggle`、toast 的关闭按钮、`.agent-tool-head`。
- 反过来的坑：`.ui-btn--primary` / `.ui-btn--accent` 是 `border-color: transparent`，被 `!important` 强改后得到"同色边"——**最重要的两个按钮反而没有可见焦点**。
- `Dialog` / `Menu`（`src/ui/overlay.tsx`）**已由 `src/ui/index.ts` 导出，但全仓库无人 import**；与此同时产品里有 **4 套手写弹层**（`buff-snapshot-panel.tsx:233`、`buff-ref-modal.tsx:104`、`admin-user-cleaner.tsx:65`、`buff-batch-regen.tsx:267`），均未做焦点陷阱。
  > **可复用的正面样板**：`share-link-picker.tsx:31-50` 是仓库里唯一把"锁 body 滚动 / 初焦点 / Esc / 关闭后归还焦点"都写对的弹层，`Dialog` 重构应直接以它为基准。
- `SelectMenu`：有 `role="listbox"` 却无方向键、无 `aria-activedescendant`、无焦点移入。
- `Toaster`：无 `role="status"` / `aria-live`，2.5s 自动消失，错误与信息**只靠颜色**区分。
- 移动端点按目标普遍 22–28px（卡片标签、词条快速选择、侧栏行、下拉项），低于 44px 建议值一半。

### 2.6 首屏与内容稳定性

| 问题 | 位置 | 影响 |
|---|---|---|
| 首页 SSR 串行：`getLatestCharElements`（**2 次 `no-store` 第三方 CDN 请求**）→ projects → announcements → auth → profile | `page.tsx:29-85`，`char-elements-latest.ts:23,31` | TTFB 取决于第三方；全站无 `use cache` / `unstable_cache` / `Suspense` |
| 服务端已拿到角色属性表**只用来校验 `?character=` 参数，随后丢弃** | `page.tsx:29-30` | 每个卡片再自己去客户端取一遍 |
| `TeamBanner` 是客户端组件，挂载后 fetch `/api/char-elements` 再重新渲染 | `team-banner.tsx:16-25` | 12 张卡 × 3 名角色 → 首次加载后**整片色块集体闪一下**；服务端 HTML 里角色名是无色灰框 |
| 路由级 `loading.tsx` 是整页 60vh 转圈 | `app/loading.tsx:5-10` | 任何 `/?q=` 导航都把刊头 + 筛选条整页清空，精心做的 2px 进度条（`globals.css:346`）**根本没机会被看到**，还有滚动跳变 |

| 卡片右下角 3 个半透明角色头像（`opacity-50`、`right-40/right-24/right-0`、最大 `size-32`）压在**浏览/克隆计数的同一横带**上 | `project-card.tsx:25-71` vs `:102-140` | 卡片最脏的一处：约 224px 的彩色人像正好垫在数字下面 |

### 2.7 主题与分享元数据

- **"深色默认"其实是"跟随系统"**：`globals.css` 的 `:root` 声明深色，但首帧脚本在无存档时优先 `prefers-color-scheme: light`（`layout.tsx:25`）—— 大多数 macOS/iOS 用户第一次进来是浅色。文档/注释说的是深色，实际行为是跟随系统，**两处逻辑还各写了一遍**（`layout.tsx:12-28` 与 `theme-toggle.tsx:22-46`，含 `#theme=` hash 透传的正则），改一处必须记得改两处。
- **没有 OG 图**：`metadata` 只有 `title` / `description`（`layout.tsx:30-36`），没有 `openGraph`、没有 `opengraph-image.tsx`、没有 `twitter` card。对一个**以分享链接为核心**的站点，这等于所有外部分享都是纯文字卡片 —— 这是低成本、高回报的一项（每张工程卡可以动态生成 OG 图：标题 + 配队头像）。
- **没有打印样式**（全站 0 条 `@media print`）：作者想打印自己的排轴表会得到带深色背景的残页。
- 无 `theme-color` / `viewport` 导出，移动端浏览器地址栏与页面底色割裂。

## 三、设计原则（取代 `ui-layout-spec.md` 的 R1）

v1 规范的核心规则是 **R1「分区靠线，不靠留白/颜色」** ——在禁用阴影的前提下，这条规则必然导致 §2.1 的结果。改为：

> **R1′ 层次只用三档手段，按此顺序优先，不得跳级滥用：**
>
> | 档位 | 手段 | 用量 | 数值 |
> |---|---|---|---|
> | 1 | **留白**（间距） | 首选，占全部层次表达的 60% | 8px 网格：4/8/12/16/24/32/48 |
> | 2 | **表面差**（背景亮度阶） | 区块分组 | bg → surface-1 → surface-2，每阶 1.10–1.25:1 |
> | 3 | **细线** | 仅两处：① 卡片**外轮廓** 1 条；② 列表/表内**行间**发丝线 | 轮廓 1px `--line`（装饰用，1.3:1 可接受）；控件描边另用 `--line-control`（≥3:1） |
>
> **R2′ 一个视野内最多两层描边**：页面级 0 层（用留白），区块级 1 层。**禁止卡片套卡片**，卡内分组一律用留白或表面差。
>
> **R3′ 语义色只表达语义**：`success / warning / danger / info` 不得用作装饰或"为了好看"的填充；主操作永远只有一种填充样式。

### 4.3 类型 token 必须改名，不要再劫持 Tailwind

/* 达标 改成前缀命名，Tailwind 保持原样；同时把 6 档写进 @theme 供 text-* 使用 */
@theme {
    --font-size-micro: 11px;
    --font-size-xs: 12px;
    --font-size-sm: 13px;
    --font-size-base: 13px;
    --font-size-lg: 15px;
    --font-size-xl: 20px;

**硬性禁令**：`text-[10px]`、`text-[11px]`、`text-[9px]` 一律清零（徽标允许 `--font-size-micro` 的 11px，且需 ≥ 3:1 对比度）。当前共 **156 处**待改。

## 五、P1 组件层：只允许一套 primitive

**现状**：`mg-card` / `ui-card` / `.workbench-item` / `.fx-row` / `.tui-row` / `<table>` / div 行 = 同一概念 7 种实现。业务页靠复制长 class 串维持外观，因此**层级永远无法被强制**。

**目标**：`src/ui/*` 作为唯一来源（它已经是好骨架，只是没人用），补齐后由业务页组合。业务页里出现裸 `<button>`/`<input>` 视为回归。

| 组件 | 现状 | 目标 |
|---|---|---|
| `Button` | 4 套（`.ui-btn` / `.toolbar-btn` / `.agent-btn` / 手写） | 1 套，5 variant × 2 size，`--r-1`、`--ctrl-h` |
| `Input/Select/Textarea` | 每页手写长串 | 1 套，描边 `--line-control`，高度 `--ctrl-h` |
| `Card` | `mg-card`(43) / `ui-card`(6) / 三层嵌套 | 1 套，**仅外轮廓 1 条线**，禁止嵌套 |
| `ListItem`（侧栏/表格行） | 3 种 DOM | 1 套：行高 40，发丝线分隔，选中 = `--surface-2` + 左 2px `--accent`（**不再整块反白**，见 4.1 支点） |
| `Dialog` | `overlay.tsx` 无人用 + 4 套手写 | 1 套，含焦点陷阱 / `aria-labelledby` / 恢复焦点 |
| `Menu` | 无 | 1 套，含 Esc / 方向键 / roving tabindex |
| `Toaster` | 无 `aria-live` | 加 `role="status"`、错误用 `role="alert"`、时长 4s |
| `PageHeader` | 4 种标题写法（`pb-2.5/4/5/6`） | 1 套，8 个公共页统一 |
| `EmptyState` | 4 种 | 1 套：图标 + 一句 + 一个主操作 |
| `ConfirmDialog`（**新增**） | 5 种"确认删除"外观 | 1 套，替代"失焦 2s 自动撤回"这类不可靠模式 |
| `StatChip`（**新增**） | 卡片元信息手写 | 1 套，12px + tabular-nums |
| `Avatar`（**新增**） | 3 处各自的 `<img>` + 兜底 | 1 套，含尺寸与占位 |

**落地手段**：先在 `/dev/ui`（local-only，`notFound()` 保护）做一个组件样本页，每加一个 primitive 放样例；业务页改动时只替换成组件，不再新增 class 串。

## 七、P3 品牌：把"鸣潮"收成一处高光

现在属性色（6 色）、角色头像、强调色、告警黄、成功绿在同屏争夺注意力。建议：

| 元素 | 允许出现的位置 | 规则 |
|---|---|---|
| 属性色（冷凝/热熔/…） | **仅**配队角色卡与属性徽标 | 只做 1px 描边 + 文字色，不做填充 |

| `--accent-solid` | 主操作、选中态 | 每屏 ≤ 1 个填充强调 |
| `success / warning / danger` | 仅状态（有效/宽限/过期、保存成功/失败） | 不做装饰 |

再叠加一条：**每屏主按钮唯一**（v1 规范里已有，实际被违反，见 6.2）。
