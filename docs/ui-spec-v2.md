> **本文件取代 `docs/ui-layout-spec.md`（v1）。**
> v1 的 R1「分区靠线，不靠留白/颜色」是当前界面"处处是框、处处不分组"的直接成因（1px 边框对比度实测 1.30–1.40:1，
> 见 `docs/ui-ux-redesign.md`）。v2 改为**层次靠版面秩序**：字号对比 → 留白 → 一条分区线。

> 视觉样张：`docs/ui-redesign-preview.html`（双击用浏览器打开，右下角可切纸/墨夜）。

## 一、六条硬规则

违反任意一条即为回归，PR 不予合并。

### H0 字族只有一种：FangXinShu

标题、正文、按钮、数字、代码块**全部**用 FangXinShu。不引入任何无衬线字体，也不引入等宽字体。

- 因为仿心书没有等宽数字（无 `tnum` 特性），`font-variant-numeric: tabular-nums` 在它是空操作 ——
  **数字对齐只能靠布局**：定宽列 + 右对齐（见 H4）。
- 兜底字体只用于加载失败，且必须同属衬线（`'Songti SC', SimSun, serif`），不得回落到无衬线。
- 12px 是下限（见 H1）：再小笔画会糊。

### H1 字号只有 6 档

| Token | 值 | 用途 |
|---|---|---|
| `--t-meta` | **12px** | 元信息、标签、表头、徽标、说明 |
| `--t-body` | **14px** | 正文、控件、列表行 |
| `--t-lead` | **16px** | 卡片标题、小标题 |
| `--t-sec` | **20px** | 区块标题 |
| `--t-page` | **26px** | 页面标题 |
| `--t-display` | **34px** | 刊头（全站仅首页一处） |

**禁止** `10px` / `11px` / `13px` / `15px` / 任意 `text-[Npx]`。
仿心书在小字号下笔画会糊，**12px 是硬下限**，这也是把正文从 13 提到 14 的原因。

> 现状违规 156 处：`text-[10px]`×60、`text-[11px]`×95、`text-[9px]`×1。

### H2 控件高度只有 2 档，同一行不得混用

| Token | 值 | 用途 |
|---|---|---|
| `--h-sm` | **32px** | 表格/列表行内操作、工具条、侧栏 |
| `--h-md` | **36px** | 表单控件、页面操作、顶栏导航 |

- 图标按钮必须是**正方形**：`32×32` 或 `36×36`。
- 同一容器内所有可点元素**等高**；徽标固定 **20px**、标签 **22px**，**不得用"缩小按钮"来表达次要**（次要 = 改 `variant`，不是改高度）。
- 行高：列表行 `44`、表格行 `40`、表头 `36`。

> 现状违规：顶栏同一行 `h-8`(32) 与 `size-9`(36) 并存（`header.tsx:12` vs `:138`）；卡片元信息行混入 `text-[11px]` 外链。

### H3 圆角 2 档，焦点环 2px

- `--r-1: 4px`（控件、徽标）· `--r-2: 8px`（卡片、弹窗）。**禁止** `rounded-full` 用于非头像元素；开关用 `999px` 是唯一例外。
- 焦点：`:focus-visible { outline: 2px solid var(--focus); outline-offset: 2px }`。
  **禁止**再用 `border-color` 冒充焦点（无边框元素会完全失效，且会把 `border-color: transparent` 的主按钮画成同色边）。

> 现状违规：实际渲染 9–10 档圆角（0/2/3/5/6/8/10/12/999）；`.ui-btn` 自身 8px 而 `--sm` 是 6px。

### H4 表头与行共用同一套列模板

```css
.row-grid { --cols: minmax(0,1fr) 72px 88px 96px; display: grid; grid-template-columns: var(--cols); gap: var(--gap); }
```

表头与每一行**必须**用同一个 `--cols`。数字列定宽 + 右对齐。

> **因为仿心书没有等宽数字（无 `tnum` 特性），对齐不能依赖字体，只能依赖布局。**
> 这一条是"行列不对齐"的根本治法：禁止用 `justify-between` + 随机 `gap` 拼一行。

> 现状违规：`admin-projects.tsx` 的 `<table>` 用 `min-w-[760px]` 且列宽不共享；`admin-users.tsx` 用 div 手拼行；`manage-project-row.tsx` 行内三段各自 gap。

### H5 一个视野最多一条分区线

层次顺序：**字号对比 → 留白 → 表面色阶 → 1px 线**。线只用于两种场合：卡片外轮廓、列表/表格行间。

**禁止卡片套卡片。** 卡内分组用留白（`--sp-4`）或表面色阶（`--s2`）。

> 现状违规：`mg-card` → 分区边框 → `.slot-card` 三层嵌套；`border-(--card-border)` 全站 204 处。

### H6 每屏只有一个实心主操作

实心绛红（`--accent-solid`）每屏仅一处，用于该页唯一主操作；其余一律描边或纯文字。
`danger` 只能出现在破坏性操作上，且必须走统一确认弹窗。

> 现状违规：详情页一屏 4 个按钮 3 种颜色，视觉最重的是"简表速览"（实心黄），而业务主操作是"下载/克隆"。

### H7 投影只有硬阴影，且"内外各一层"

**模糊半径恒为 0。** 投影只用 1–6px 的硬偏移叠厚度，像把纸片压在纸上；`blur > 0` 会把边缘糊成一团，卡片叠在卡片上也看不出层次。

三档令牌（纸 / 墨夜各一套）：

| 令牌 | 语义 | 硬偏移 |
| --- | --- | --- |
| `--wk-elev-1` | 卡片、输入框、编辑面板「离开纸面」 | `0 1px 0` + `0 2px 0` |
| `--wk-elev-2` | 浮层（菜单、下拉面板、弹窗、toast） | `0 2px 0` + `0 6px 0` |
| `--wk-btn-shadow` | 按钮（默认 / 主 / 危险 / 幽灵） | `0 1px 0` |
| `--wk-elev-up` | 粘底操作条（保存条 / 操作栏）向上投影 | `0 -1px 0` + `0 -3px 0` |
| `--wk-inset-1` | 内凹：输入框、编辑框、分段（tabs）容器、开关 | `inset 0 1px 0` 暗 + `inset 0 -1px 0` 亮 |
| `--wk-inset-2` | 上缘高光 + 下缘压暗：卡片、浮层、选中项、徽标 | `inset 0 1px 0` 亮 + `inset 0 -1px 0` 暗 |

组合式用法（外 + 内写在同一处，别分两层元素去凑）：`box-shadow: var(--wk-elev-1), var(--wk-inset-2)`。

**必检面**：`.wk-card` / `.wk-panel` / `.wk-slot` / `.wk-acc`（卡片）、`.wk-input` `.wk-textarea` `.wk-select` `.wk-dd-trigger`（编辑框）、`.wk-seg` + 选中项（tabs）。
`.wk-btn--quiet` 是唯一允许 `box-shadow: none` 的按钮（三级操作靠底色表达，避免密集行里一片投影）。
由 `node scripts/check-shadow.mjs`（也已并入 `check:accept` 第 14 项）回归：任何 `blur ≠ 0` 的投影、或必检面缺内外阴影，都会判 FAIL。

## 三、编辑锁：从页脚搬到顶栏

现状问题：`.ws-shell` / `.ws-plain` / `.agent-shell` 都是 `position:fixed; top:3.5rem; bottom:0`，**把页脚整个盖住**；
而锁定页的提示恰好让人"去首页底部关锁"（`app/edit/buff-sets/page.tsx:32`）—— 在需要它的页面上不可达。

**新位置**：顶栏最右侧一个锁形图标按钮（仅管理员可见），点击弹 popover：

```
[锁•]  ← 有任一锁定生效时显示小红点
      ┌────────────────────────────┐
      │ 编辑锁 · 管理员             │
      │ Buff 集锁定        [开关]   │
      │ 标准词条集锁定      [开关]   │
      │ 锁状态对所有访客生效        │
      └────────────────────────────┘
```

- 页脚只保留一行：`椰果工坊 · 与椰果工具箱搭配使用` + 版本号。**不再放任何交互控件。**
- popover 用统一弹层组件（细边 + `--elev-2` + Esc + 焦点归还）。

### 3.1 条目级锁的入口（两把锁的第二把）

顶栏那把是**域级**锁（整个 Buff 集 / 标准词条集）。**单个实体**的锁在各自的编辑台里，位置固定：

| 编辑台 | 入口 | 组件 |
|---|---|---|
| `/edit/buff-sets` | 实体信息头右侧的锁图标（仅管理员） | `BuffEntityEditor` 头部 |
| `/edit/substat-sets` | 工具条右侧、`更多` 左边的锁图标（仅管理员） | `SubstatEditor` 工具条 |

约定：

- 锁定时图标换成实心锁并着 accent 色；Buff 编辑台的**标签页**上还常驻一把 11px 小锁，不切页也能看出哪个实体被锁。
- 切换立即生效（`router.refresh()` 重新下发 `buffLocks`），不加二次确认——它可逆、非破坏性，和删除类操作不同。
- 域级锁优先级更高：域级锁开着时，条目级锁怎么设都不影响「仅管理员可写」的结论。
- `scripts/check-lock-ui.mjs`（已进 `check:all`）会断言 `setBuffSetLock` / `setSubstatSetLock` **至少各有一处调用**——这两个 action 曾经因为编辑台重写丢掉入口，变成"锁还在生效但找不到开关"。

## 四、管理台 / 编辑台（全部重做成同一套，单列）

四套并存（`.workbench-*` / `.ws-*` / `.edit-*` / `.buff-admin-shell`）合并为一套。

**不做 VSCode 的「活动栏 + 永久对象侧栏」，但采用它的「工作区顶部标签页」。** 上一版把三栏工作台整体否掉，理由仍然成立：

1. 左侧常驻列表长期只服务"切换对象"这一件事，却永久吃掉 240px，把编辑区挤成窄条；
2. 右侧同时堆了快照、批量重生成、AI、导入导出等**与当前编辑无关**的东西，屏幕被切成碎片，视线没有落点。

标签页与侧栏的区别是：**标签只表示"已经打开的对象"，没打开就占 0 宽**；打开对象走一次性弹窗，不占任何常驻空间。

```
┌──────────────────────────────────────────────────────────┐
│ 页面标题                                        快照 3.8.5 │ ← 低频工具只在页头
├──────────────────────────────────────────────────────────┤
│ 碎梦亡鬼之魔 ×│ 焚羽猎魔之影 ●×│ 命理崩毁之弦 ×│ ＋    未保存 1 │ ← 工作区标签（卡片内）
├──────────────────────────────────────────────────────────┤
│ 套装  碎梦亡鬼之魔   1 条 Buff                            │
│ 组名 [____________]   Buff 名 [______________________]     │
│ [自己│队友│全队│效应]                    删除该条           │
│ 链/阶条件 ▸                                               │
│ ┌ 乘区条目 ─────────────────────┬ 添加乘区 ──────────────┐ │
│ │ 普攻/重击加成  [35] % 追加 条件 ×│ 攻击 · 暴击 · 增伤 …   │ │
│ └────────────────────────────────┴────────────────────────┘ │
│ 已保存                                  删除实体 ······ 保存 │ ← 粘底操作条
└──────────────────────────────────────────────────────────┘
```

三条铁律：

1. **不做常驻左侧对象列表。** 打开对象用「打开对象」弹窗：搜索框 + 类型分组（角色 / 武器 / 声骸 / 套装），类内按名称排序、带条目数与锁定标记；一次只服务一个对象。
2. **低频工具各自只出现一次，且不折叠成菜单。** 快照固定在页头；删除整个实体在底部操作条（二次确认）；AI / 导入导出留独立页面。**全站不再用「更多」下拉收纳低频操作**（批量重生成已删除：它与快照的职责重叠，且快照本身就能回滚）。
3. **编辑区单列、字段竖排（label 在上、控件在下）。** 名称类字段一律单行输入框；行内数据用行网格，不用左右分栏。仅「乘区条目 ↔ 添加乘区」保留左右分栏：左边是已加入的条目，右边是常驻的可选项清单，两者是同一件事的两半。

**统一的行为约定（现状各页不同，全部拉平）**

| 约定 | 现状 |
|---|---|
| 同一时刻只显示一个对象；脏状态用徽标显示在标题行 | 只有 Buff 编辑器有；`/edit/substat-sets` 无脏状态 |
| 底部粘性保存条（状态 + 丢弃 + 保存），未脏时保存禁用 | 保存按钮夹在工具条中段，未脏仍可点 |
| 行内操作最多 2 个，其余进「更多」 | 一行塞 4 个 10px 图标按钮 |
| 破坏性操作统一 `WkConfirm`（不用"失焦 2s 自动撤回"） | 3 处用自动撤回，5 种外观 |
| 有未保存改动时 `beforeunload` 拦截 | 全仓库 0 处 |
| 所有弹层用同一组件 | 4 套手写 + 1 套没人用的 `Dialog` |
| 多行框不可拖拽高度：`resize: none` + 自动增高 + 上限 40vh | `resize: vertical`，用户会把页面拽乱 |
| 窄屏（≤900px）：单列天然可用，不需要抽屉或折叠 | `.ws-sidebar{display:none}` → `/edit/buff-sets` 手机完全不可用 |
| 表格窄屏卡片化，禁止横向滚动找操作列 | `min-w-[760px]` |

## 四·补、工程卡：保留头像叠底，但必须"不压字"

头像叠底是这个产品的品牌视觉，**保留**。问题不在叠底本身，而在旧实现把 3 个 `opacity-50` 的大头像
（最大 `size-32`、`right-0`）正好垫在浏览/克隆计数的那条横带上，读数被彩色人像干扰。

三条约束（缺一不可）：

| # | 约束 | 实现 |
|---|---|---|
| 1 | 叠底**不抢点击** | `pointer-events: none` |
| 2 | 叠底在内容**下面** | 叠底 `z-index: 0`，内容层 `z-index: 1` |
| 3 | 叠底**朝文字方向淡出**，且元信息行铺**实色底** | `mask-image: linear-gradient(to left, #000 42%, transparent)`；`.wk-card-foot { background: var(--wk-s1) }` |

对应类：`.wk-card-art` / `.wk-card-inner` / `.wk-card-foot`（见 `src/design/wk.css`）。
叠底的透明度与头像尺寸由组件按头像数量给；**文字区域永远是实色背景上的文字**。

## 五、落地顺序

不一次性重写。新系统并行存在，逐页替换，站点全程可用。

**进度（全部页面已落地）**：广场、工程详情（Markdown）、我的、上传、登录、设置用户名、启动器落地页、404、配置提示、
Buff 集 / 标准词条集浏览、工程管理、管理员管理（授权树）、Buff 集编辑台、标准词条集编辑台、AI 控制台（暖色/墨夜 + FangXinShu）。

**仍保留的旧内部组件**（外壳已是新系统，内部表单仍是旧写法，故列在 `scripts/legacy-allowlist.txt`）：
`BuffSnapshotPanel`、`BuffRefModal`、`SubstatSlotEditor`、`AgentConsole`。它们之后整体重写时一并迁出豁免名单。

**编辑台统一骨架**（已落地，后续沿用）：页面头部放低频工具（如快照）→ 一张卡片内的 VSCode 风格工作区标签页
→ 单列编辑区（字段竖排）→ 粘性保存条（未脏禁用保存）→ 一切破坏性操作走 `WkConfirm`。
**切换对象不丢草稿**：每个打开过的对象固定挂载一个编辑器实例，未激活的只隐藏不卸载。
**长任务工作台锁一屏**（`/edit/*`）：页面不滚、标签栏钉顶、保存条钉底，只有中间内容区滚动。

**兼容桥（已删除）**：旧变量名到新令牌的映射随旧组件一起移除；现在只有 `--wk-*` 一套令牌。
